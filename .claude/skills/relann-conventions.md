## juplit workflow (`.py` is source of truth)

- This repo uses **juplit**: every `.py` file under `relann/` and `examples/` has a jupytext header that pairs it with a `.ipynb`. The `.py` is the source; the `.ipynb` is generated by `uv run poe sync` (or `juplit sync`) and is gitignored.
- Cells use `# %%` (code) and `# %% [markdown]` (prose). Inline tests / asserts must be wrapped in `if test():` (from `juplit`) so they don't execute on plain import.
- **Never** edit `relann/*.ipynb` directly — those are generated. Edit the `.py`.
- There are no `#|export` / `#|hide` directives. All code in a `.py` file is exported by default.

## Module ↔ notebook mapping

There is no separate `nbs/` directory anymore. Each module under `relann/` *is* the paired notebook. To open it interactively in Jupyter, run `uv run poe nb` (after `uv sync`) to materialise the `.ipynb`, edit it, then `uv run poe sync` to push changes back to the `.py`. Cleanest workflow for AI agents is to edit the `.py` directly.

## Notebook merge conflicts

`.ipynb` files are gitignored, so the only conflict surface is the `.py` source. Resolve as normal text merges. After the merge run `uv run poe sync` to regenerate the `.ipynb`.

## Jupyter MCP execution policy

- A Jupyter MCP server (JupyterLocal) may be available for executing notebook cells.
- All execution must use the **project's uv venv** (`.venv/`) unless otherwise specified — `uv run jupyter lab --no-browser --port 8888` if you need to start the server.
- Never reason about notebook behavior without executing cells via MCP.
- When instructed to run a notebook:
  1. Execute cells in order via MCP.
  2. On the first failure: read the failing cell source and full traceback, diagnose the root cause, apply the smallest possible fix, re-execute the same cell.
  3. Continue until all target cells succeed.
- Do not modify passing cells.
- Do not reset the kernel unless explicitly instructed.
- Summarize all changes at the end.

## Safety constraints

- Max retry attempts per cell: 3.
- Never install packages without explicit instruction.
- Prefer inserting a new cell over rewriting complex logic.

## Code style

- Do not wrap project imports (e.g. `relann.utils.custom_transformation_modules`) in `try/except` — assume they're available.
- Production code goes outside `if test():`; assertions, fixtures, and example sessions go inside.

## After bulk edits to `relann/*.py`, regenerate `.ipynb`

If you edit any `relann/*.py` or `examples/*.py` file from outside Jupyter (text editor, a script, an AI agent) and a corresponding `.ipynb` already exists on disk, **always run `uv run poe nb` (or `uv run poe sync`) before opening the notebook in Jupyter**. Otherwise Jupyter reads the stale `.ipynb` from disk and you'll see the OLD code (e.g., old import statements that no longer match the `.py`).

The safe recovery if you see stale content is:
```bash
rm -f relann/*.ipynb examples/*.ipynb .sync_hashes.json
uv run poe nb
```

This is especially important after import / API renames done by scripts or AI agents.

## Inline demos in source modules are NOT guaranteed to run in linear order

`relann/*.py` files (especially `engine.py`, `parser.py`, `relnn.py`) contain inline demo cells in `if __name__ == "__main__":` blocks. These were `#| hide` / `#| eval: false` cells under nbdev — meant for interactive notebook reading, not automated execution. Several rely on methods that `@patch` adds to `Engine` *later* in the same file, so "Run All Cells" in Jupyter or `python relann/engine.py` from a shell will hit `AttributeError` partway through. Tests in `tests/` do NOT run these cells.

Treat them as readable documentation. If a user reports "demo at line N broke," check `docs/design/notebook-demos.md` for the known-broken list and the decision tree on how to fix.

## Imports inside `relann/`

- **Top-level files in `relann/*.py`** (the juplit-paired modules) must use **absolute** imports: `from relann.term_graph import TermGraph`, never `from .term_graph import TermGraph`. Reason: these files are also opened as Jupyter notebooks. When Jupyter executes a cell, the file is not loaded as a member of the `relann` package, so relative imports fail with `attempted relative import with no known parent package`.
- **Subpackage files** (`relann/utils/*.py`) keep conventional **relative** imports (`from .algebra import …`). These are never opened as notebooks.
- This is a known juplit-specific quirk. Don't "fix" the absolute imports in top-level files back to relative — Jupyter will break.

## Debugging with logging

- Every module in `relann/` has a module-level `logger = logging.getLogger(__name__)`.
- To enable debug output for a specific module in a notebook, use the `checkLogs` context manager:
  ```python
  from relann.log_utils import checkLogs
  with checkLogs(name='relann.engine'):  # or 'relann' for all modules
      ...  # debug logs from that namespace will print
  ```
- `checkLogs` is temporary — log level reverts when the `with` block exits.
- To write logs to a file: `checkLogs(name='relann.engine', toFile='debug.log')`.

## HGT and RelaNN correctness

- **Row-first layout (global convention)**: Embeddings are always **(num_rows, *feature_dims)** — dim 0 is the row dimension. All tensor operations use the smart ops in `relann/smart_ops.py` (`smart_mul`, `smart_matmul`, `smart_transpose`, `smart_view`, etc.) which preserve dim 0 and operate only on feature dims. See `docs/design/row-first-tensor-convention.md` for the full contract.
- **No patches**: Fix bugs in RelaNN (`relnn`, `era_operations`, `engine`) or in rule definitions; do not add engine/op workarounds that reshape or reinterpret wrong shapes (e.g. no fallback in `_ArithmeticWrapper` that reshapes `(E,1,96)` to `(E,h,1)`).
- **HGT shapes**: Attention must output `(E, h)` per head (scalar per edge per head); after Concat, `(E, h)`. In AGG_MSG, message is `(E, h, d/h)`, attention `(E, h, 1)` via `unsqueeze(-1)(z1)`. Transformation must not pad `(N, 1)` to `(N, d/h)`; only genuine square `(N, N)` with `N>1` is projected/trimmed by `expected_embedding_tail`.
- **Tests**: Use `tests/slow/` for HGT and the full test suite to verify shapes; fix root cause if a test fails.
